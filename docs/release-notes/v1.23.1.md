# v1.23.1 release notes

These notes describe the v1.23.1 feature set. Check the [GitHub releases page](https://github.com/Holden-Lin/claudex-switch/releases) for current availability.

- **Small-window models compact at ~90% instead of erroring.** Managed OpenCode V2 sessions (API-key and Console subscription) whose smallest model window (the selected model and the default agent's model) is below 500,000 tokens now keep auto-compaction on and write a session-only `compaction.buffer` — about 10% of the window, never below OpenCode's own 16,000-token minimum — into that run's managed config, so compaction fires at about 90% of the window. The override is written to that run's managed config only; the user's global `opencode.jsonc` is untouched, and windows ≥ 500,000 keep the user's own compaction settings.
- The basis follows OpenCode's real trigger formula `limit.input || limit.context`, and metadata-less models use OpenCode's 200,000-token fallback window. A user buffer that is smaller than the computed one but still leaves OpenCode's minimum margin is kept as-is (it compacts later than 90% but still fires above zero).
- Why: v1.23.0 fixed the endless-compaction loop (a global `compaction.reserved` of 500,000 on a 200k-window model made OpenCode's trigger `window − buffer` ≤ 0, so every turn compacted) by disabling auto-compaction for small-window models — but a full window then errored instead of compacting. This release keeps compaction enabled and moves the trigger to ~90% of the window instead.
