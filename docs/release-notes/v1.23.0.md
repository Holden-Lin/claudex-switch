# v1.23.0 release notes

These notes describe the v1.23.0 feature set. Check the [GitHub releases page](https://github.com/Holden-Lin/claudex-switch/releases) for current availability.

- **OpenCode V2 headless one-shots.** `claudex-switch <alias> -run run [--format json] "<prompt>"` runs `opencode run` in the current directory on the alias's private standalone server, managed Go model, and synced key. The message and `--format` / `--thinking` / `--title` / `--file` / `--print-logs` are forwarded; directory, resume/session (`-c` / `-s` / `--session` / `--fork`), `--model` / `-m`, `--agent`, `--server`, and unknown arguments stay refused.
- **Small-window models no longer fall into endless auto-compaction.** Managed OpenCode V2 sessions (API-key and Console subscription) disable auto-compaction for a session when the smallest model window it starts with (the selected model and the default agent's model) is below 500,000 tokens. The override is written to that run's managed config only (`compaction.auto=false`); the user's global `opencode.jsonc` is untouched, and windows ≥ 500,000 keep the user's own compaction settings. With compaction disabled, a full window errors instead of compacting.
- Why: OpenCode auto-compacts once a session exceeds `window − reserved` tokens. A global `compaction.reserved` of 500,000 with a 200k-window model (for example a free model) makes that trigger ≤ 0, so every turn compacted — the endless-compaction failure reproduced on 2026-10-15. Models with a 500,000-token window keep the user's settings, so at exactly that boundary a 500,000 reserved still compacts every turn.
